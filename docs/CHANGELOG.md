# 작업 기록

## 2026-11-08 — 스토리 맵 (Photoshop 디자인 → 실제 화면)

- 사용자가 다듬은 `VEIL_스토리맵_UI.psd`를 원본은 그대로 두고 복제본에서 내보냄 → `assets/ui/story_map/` (배경, 고정 UI, 노드 7개, 배지 2종, `story_layout.json`)
- 스토리 화면을 `scripts/ui/story_map.gd`로 교체: PSD 좌표 그대로 배치(화면 대조 결과 평균 픽셀 오차 2.8/255, JPEG 수준)
  - 숫자만 Godot에서 그림: 에너지 `현재 / 240`, 크리스탈, 임무 진행 `클리어 수/10`
  - 진행 숫자 글꼴: PSD의 Bahnschrift(Windows 내장, 배포 불가)를 Rajdhani Bold/SemiBold로 대체
  - 핫스팟: 뒤로·엠블럼 → 로비, 메뉴 → 설정, 장막 좌우 → "준비 중", 배너 → 이벤트, + → 상점, Esc → 로비
- 노드 → 스테이지 정보 창(`StagePopup`) → 「출격」 → 전투. 결과 화면 → 스토리 맵으로 복귀
- 스테이지 데이터 `StageDefs`: 1-1·1-2(메인), S1-1~S1-3(서브 의뢰), R1-1·R1-2(기록 재생, 전투 없음)
  - 해금 조건(1-2 ← 1-1, S1-3 ← S1-2), 잠김 노드는 어둡게 + 잠금 배지, 해금 시 V 등급 배지
  - 스테이지별 적 배치·배율(HP·공격력 ×0.85~×2.0), 에너지(8~15), 보상 배율
- 테스트 252개 통과 (스토리 맵 흐름·잠김·기록 노드·해금·적 배율 추가)

## 2026-11-08 — Phase 3: 캐릭터 4종 · 전투 · PDF 화면 전체

기준 자료: 사용자 제공 캐릭터 기획 PDF (16쪽: 스테이지 · J · 라 · 페이즈 스킬 프리뷰/캐릭터 시트, 캐릭터 정보 화면 3종, 로비 화면).

### 결정 (사용자, 11/8)
- 라 = 근접 탱커, J·스테이지 = 딜러. 페이즈 = 근접 서포터 (PDF 내용 기준 해석)
- 4명 모두 출전: J 직접 조작, 나머지 3명 AI (스킬 1/2/3, 궁극기 Shift+1/2/3)
- 궁극기 = 오염도 100% + PDF 쿨타임
- PDF 화면 전부 구현: 모집·상점·배틀패스 포함, 실제 결제 없음 (로컬 재화만)

### 구현
- 캐릭터 데이터 4종 (`data/characters/*.tres`): PDF 스탯·스킬 문구·속성·키 그대로, 일러스트·초상은 PDF에서 잘라 씀
- 전투: 640×360 픽셀 화면 ×3, 4인 파티, 스킬 8종, 상태이상 12종, BITE 적 3종, 단말 → 출구 목표, 승리·패배·보상
  - J: 생명의 대가(짧게 관통 / 길게 은신 20초), 어둠속의 그림자(방어 무시·속박 5초 → 은신)
  - 스테이지: 콤보!(5연발·스택·공속·전도 +20%), 크래킹(스택 소모 광역 + 픽셀 폭발)
  - 라: 불굴의 태양(쌍창·광휘 창 2회·실명), 심판의 날(아군 30.6% 회복·부활 50%·공격 +25%·초당 5%), 태양 코어 특성
  - 페이즈: 차원 개방(부채꼴·둔화·광속 질주·쿨 초기화), 차원 질주(포털 게이지 3pt/초, 아군 이속·공속, 적 내성 -20%)
- 로비와 하위 화면: 스토리, 캐릭터 정보(정보/육성/조각/스킬/무기/프로파일), 모집(천장 50), 상점, 배틀패스, 파견임무(실시간), 우편, 공지, 이벤트, 커뮤니티(오프라인 안내)
- 세이브: `user://saves/slot_1.json`, 버전·검증·마이그레이션·.bak 복구, 에너지 6분당 1 회복
- 타이틀: 이어하기 / 새 게임(덮어쓰기 확인), 설정에 "동료 스킬 자동 사용"
- Figma: 04 로비 · 05 캐릭터 정보 · 06 전투 HUD(4인) 프레임 추가

### 가정 (PDF에 없거나 모호해서 임시로 정한 것)
- 라 궁극기 쿨타임 30초, 페이즈 일반 스킬 쿨타임 6초
- 페이즈 스탯 전부 (PDF에 정보 화면 없음)
- 능력치 6종의 4~6번째: 치명타 확률 · 치명타 피해 · 효과 적중으로 해석
- 페이즈 "공격 속도 수치의 35%" → 공격력 175%로 임시 계산, "내성 감소 20%" → 주변 적이 받는 피해 +20%
- 스테이지 콤보!는 1초 동안 5연발로 구현 (12초 쿨타임 안에 스택 5를 쌓을 수 있게)
- 모든 캐릭터는 처음부터 보유, 모집 결과는 조각·크레딧
- J가 쓰러지면 작전 실패
- 1m = 4px (J 은신 사거리 +15m = +60px)

### 테스트
- 자동 검사 221개 통과 (전투 18 · 세이브/육성/모집/상점/패스/파견/우편 9 · 화면 흐름 3 등)
- AI 전투 시뮬레이션: 90초 안에 적 전멸
- 가상 디스플레이에서 화면 9장 캡처로 표시 확인
- **미검증**: 실제 키보드·마우스 조작감, Windows/macOS 창 실행, 소리(없음)

## 2026-11-08 — Phase 2: 프로젝트 구축

### 구현
- Godot 4.7.2 프로젝트 생성, 기획서 4장 폴더 구조 적용
- 오토로드 5종: EventBus(신호 중계), InputConfig(행동·키 등록), SettingsManager(설정 저장·검증·적용), GameManager(상태·일시정지), SceneManager(페이드 씬 전환)
- 화면: 부팅 → 타이틀(새 게임/설정/게임 종료) → 테스트 맵(빈 화면) → 일시정지(계속/설정/타이틀로)
- 설정: 전체 음량, 창/전체 화면, 해상도 3종. 바꾸는 즉시 적용·저장. 손상 파일은 `.corrupt`로 보관 후 기본값
- 현지화: 모든 화면 문구를 번역 키로 작성 (ko, en)
- 폰트: Noto Sans KR(본문 400/제목 700), Rajdhani(로고·숫자) — 둘 다 OFL
- UI 색상은 Figma 「VEIL — 프로토타입 UI」의 VEIL Color 변수와 같은 값(`scripts/ui/ui_style.gd`)

### 기술 결정
- 렌더러 GL Compatibility: 2D 게임이고 저사양 PC·모바일까지 같은 렌더러로 맞추기 위함
- 입력 행동은 코드로 등록하고 물리 키 위치를 사용: 한글 자판 상태와 무관하게 동작, 이후 키 변경 기능에 그대로 사용
- 테스트 도구: 기획서의 GUT 대신 자체 실행기(`tests/run_tests.tscn`) 사용. 외부 의존성 없이 오토로드와 실제 씬까지 검사 가능. 테스트가 늘어나면 GUT 도입 재검토
- 창 기본 크기 1600×900 (화면보다 큰 해상도를 고르면 화면에 맞는 최대 해상도로 줄임)

### 테스트 결과
- 자동 테스트 12개 함수 / 검사 70개 통과 (설정 저장·검증·손상 처리, 입력 등록, 전체 화면 흐름)
- 헤드리스 실행 300프레임: 오류·경고 0
- 가상 디스플레이(Linux)에서 화면 4장 캡처로 표시 확인
- **미검증**: 실제 Windows/macOS 창에서의 실행, 전체 화면 전환, 해상도 변경, 소리 (사용자 PC 확인 필요)
